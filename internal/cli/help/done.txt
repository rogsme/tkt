tkt done closes the ticket's tabs and removes its worktree once its pull
request is merged. worktrunk deletes the branch when it is merged into the
base; after a squash merge the branch stays.

It keeps the worktree, and says why, when:
  - the pull request is still open, or no merged pull request has the branch;
  - the worktree has uncommitted changes;
  - the branch tip is neither the merged head nor in the base;
  - an agent in the worktree works or waits for an answer;
  - tkt runs inside the worktree or in the ticket's own tab;
  - a pane outside the ticket's tabs, or the OpenCode service, works in it.

--all checks every ticket worktree and asks before removing them; pass --yes
when stdin is not a terminal. It reads pull requests through gh, so it
supports GitHub forges only.

It records the merge in the history, so tkt stats can say how long the ticket
took from tkt start to the merge.
