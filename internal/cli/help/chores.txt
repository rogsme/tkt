A chore is an agent run you schedule, such as a dependency upgrade. Each run
is a branch and, unless the chore sets pr = false, a pull request, with no
ticket. tkt ships no chores: you
define them in the repository's .tkt/tkt.local.toml, your own file in its
main checkout, so each person's chores run once (tkt help config):

  [chores.deps]
  schedule = "0 9 * * 1,4"     # cron's five fields, in local time
  branch = "deps-{date}"       # {name}, {date} and {time}; the default is {name}-{date}
  as = "fast"                  # the preset; leave out for the default
  pr = true                    # false when the work lands elsewhere; the default is true
  prompt = "Upgrade the dependencies. Read each migration guide, and note the breaking changes in the pull request."

That repository's tkt watch starts a run when its slot comes. A run gets a
branch from the base on the remote, its own worktree and tab, and an agent
with the chore's prompt and one rule: commit on the run's branch, push it,
open one pull request to the base, and end with Status: READY_FOR_REVIEW
once it is open, or with Status: DONE, committing nothing, when there is
nothing to change. The run's id is its branch, such as deps-2026-10-26: tkt
ls lists it beside the tickets, and tkt run, sync, show, send, hold, resume,
wait, history and done take it.

From there tkt watch treats the pull request as it does a ticket's: it
merges a moved base when a sync is due, and runs ci once per head when the
checks fail. No skill reviews, fixes or merges a pull request without a
ticket, so tkt ls says when the review bot found something, and when the
pull request is ready for you to merge. Merge it yourself and run tkt done
once you finish with the run, or close it to drop the run: tkt watch then
removes the run, and removes at once a run that ended with nothing to
change. tkt run refuses a run the stages that need a
ticket, such as review and address, and tkt approve, tkt auto and tkt merge
take tickets only.

A chore whose work lands somewhere other than a pull request, such as a tag
and a release on the forge, sets pr = false:

  [chores.release]
  schedule = "0 10 * * 5"
  pr = false
  prompt = "If main has commits since the last tag, tag main with the next version and publish its release with gh."

Its agent gets another rule: open no pull request, commit nothing on the
run's branch, and end with Status: DONE once the work is done, or with
Status: BLOCKED and a Reason: line when it cannot be done. tkt watch removes
a run that ended with Status: DONE at once, as it removes one with nothing
to change, and a run that stopped with Status: BLOCKED waits for you. A
commit on the branch keeps the run, since tkt done never drops one.

A run whose start stopped before its agent got the prompt, as at a startup
dialog or on a pre-start hook that failed, waits for you and holds the
chore's next slots: tkt chore run NAME goes on with it in its worktree, and
tkt done drops it. A run never takes the branch of an older one, or of any
pull request, since tkt finds a run's pull request by its branch.

A prompt that runs a slash command, such as /upgrade-dependencies, goes
alone and on one line, since the command would read the rule as its
arguments: the command says how the run ends, and a run that ends with
neither a pull request nor Status: DONE waits for you.

A slot that passes while the chore's last run is still open is skipped, so
one run waits for you at a time. A slot missed while no tkt watch ran runs
once when one runs again, however many passed. The first tkt watch to see a
chore starts its first run at its next slot. While a status page reports an
incident, a due run waits, as every agent run does (tkt help watch).

tkt chores lists the repository's chores: the next slot, the last one tkt
watch took or skipped, and the run still open. With --json each chore also
carries its prompt, as you wrote it, without the rule tkt adds. The tkt
agent's web page shows it under the chore. tkt chore run NAME starts a
run now, and refuses while the chore's last run is open, unless that run's
start stopped before its agent got the prompt: then it goes on with it.

A chore that needs no agent, such as npx skills update, belongs in a plain
systemd timer or cron job, without tkt.
