tkt suggest has the suggest-tickets skill pick the next tickets to start.
It opens a suggest tab at the repository's root, or reuses it, starts a
fresh session there, and sends it what you ask, after the skill's name:

  tkt suggest five tickets tagged feedback
  -> Use the suggest-tickets skill for this request: five tickets tagged
     feedback

suggest-tickets takes the number your request names, and narrows the
candidates by what else it says, such as a label, an area or a model. With
no words, or only a count, tkt sends the suggest line for that many tickets,
3 by default:

  Use the suggest-tickets skill to suggest the next 3 tickets to start, ones
  that can run side by side.

suggest-tickets only reads. It lists the ready tickets, keeps the ones
whose blockers are all done, and ranks them by how many tickets wait on
each, then by priority. It drops one that would collide with work in
flight, judged from the files each in-flight branch changes, or with
another pick, and with model routing on it takes at most one heavy ticket.
It reports what waits on you first, then the picks and what it left out,
and ends with a line such as

  Suggested: ACM-14 (frontier), ACM-21 (acme-small-2)

The session runs on the [suggest] preset (tkt help config), or the default
preset; --as picks another, such as a cheap one.

tkt suggest returns once the agent has the prompt, and reads nothing it
says. The answer stays in the tab: read it there, ask the agent about it,
and start the tickets you want with tkt start, adding --as PRESET for a
ticket that should run on another preset. The tkt agent's /suggest opens
the same tab.

tkt suggest --show prints what the last run's agent said since its last
prompt, read from its session's record the way tkt show reads a ticket's,
or from its screen when tkt cannot read the record. It starts nothing, so
the web page's Suggest view polls it to show the picks.
