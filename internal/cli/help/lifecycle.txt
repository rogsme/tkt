Each step is one command you run or one answer you give in the ticket's tab.
tkt ls shows where every ticket stands and suggests the next step.

1. Start the ticket: xclip -selection clipboard -o | tkt start --prompt -
   with its start-ticket block on the clipboard, or tkt start ACM-12 to send
   only the start stage line. The agent investigates and ends with
   Status: AWAITING_APPROVAL.
2. Read the plan with tkt show ACM-12, then approve it with tkt approve
   ACM-12, or ask for changes with tkt send ACM-12 "what to change". Both
   type into the planning session, which goes on to implement the plan with
   work-ticket; tkt run would start a fresh session and discard the plan.
3. When the agent ends with Status: READY_FOR_REVIEW, run tkt run ACM-12
   review. The reviewer must not be the session that wrote the change, and
   tkt run always starts a fresh one.
4. Act on the verdict the review posts. On CHANGES_REQUESTED, run tkt run
   ACM-12 address, which merges the base first and then answers the review.
   It ends with Status: READY_FOR_REVIEW, so go back to step 3. When the base
   moved instead (Status: BLOCKED_FOR_SYNC, the bot's STALE_BASE, or a
   conflict), run tkt sync ACM-12: it merges a clean base itself and hands a
   conflict to a fresh session. On READY_FOR_HUMAN, or the review bot's
   CLEAR, go on.
5. Do the human verification steps (tkt show ACM-12 --steps). tkt run ACM-12
   verify has an agent run them in a browser and report each one, but you
   decide whether each step passed.
6. Once every step passed, run tkt merge ACM-12 --passed 1-3. It sends a
   fresh session finish-ticket's explicit word to merge, naming the steps;
   while the checks still run, it leaves a merge order that tkt watch carries
   out once they pass. When a step failed, tell the agent in the tab what you
   saw instead; it ends with Status: HUMAN_QA_FAILED, and you run tkt run
   ACM-12 address. When it ends with Status: BLOCKED_FOR_SYNC, another merge
   moved the base: run tkt sync ACM-12, and the review starts again.
7. After the merge, run tkt done ACM-12 from another tab.

When the checks fail at the pull request's head and no review is waiting to be
addressed, run tkt run ACM-12 ci.

tkt watch, which tkt starts by itself, syncs a moved base when a sync is due,
runs ci once per head when the checks fail, carries out merge orders, and
runs step 7 once finish-ticket ends with Status: DONE, for every ticket that
is not on hold.

tkt auto ACM-12 takes steps 3 and 4 for you, and step 2 too with
--approve-plan: it waits for CI and the review bot, syncs a moved base, runs
address and ci in fresh sessions, pauses when the ticket needs you, and stops
when the head is reviewed clean. Steps 5 to 7 stay yours. tkt agent does the
same from a chat, for many tickets at once.
