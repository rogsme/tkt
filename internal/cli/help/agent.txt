tkt agent opens a chat in this pane about the repository's tickets. It runs
pi, a coding agent that release builds of tkt carry inside them (MIT licensed,
https://github.com/earendil-works/pi), with only tkt's own extension. Running
tkt with no arguments opens it too, when you type it at a terminal in a herdr
pane inside a repository with the lifecycle configuration.

Say what you want in plain words: "start ACM-12", "run ACM-13 to ACM-15 in
auto with sol", "I approved the plan for ACM-12, continue", "ACM-12 is merged,
remove it". Starting tickets and stages runs in the background and the prompt
comes back at once, so you can start the next ticket while the first one
plans. A board pinned to the top of the chat shows every ticket, and on top
what needs you: a plan to approve, a question from its agent, a pull request
ready for human verification, or a tkt auto loop that paused for you. The chat
scrolls below the board, so it covers nothing. An item leaves the board as
soon as its ticket moves on, and the chat stays free of them. Each new one
also shows a herdr notification. Each row shows what the branch changes,
such as +293 -8, and the pull request's title, and marks a chore's run. When
a status page reports an incident, the board says so at its top. /board hide
and /board show put the board away and back.

Ask how a ticket went, merged ones too: "how did ACM-12 go?", "what failed
in ACM-12 and ACM-13?". The chat reads tkt history: each step with its time,
and the pull request's commits and reviews with the review bot's findings.

The same actions work without the model as slash commands: /suggest (a
fresh agent in a suggest tab says which tickets to start next; add what you
want, such as /suggest five tickets tagged feedback), /start (add "as
PRESET" for a preset), /approve, /next, /auto, /hold, /sync, /send, /show,
/peek (the agent's live screen), /check (the human verification checklist,
which offers to sync a ticket that is behind first), /done, /inbox (what needs
you, with fixed answers), /board (every ticket in columns), /chores (the
repository's chores; /chores run NAME starts a run now), /history, /stats
and /update. A tool that changes a ticket your message did
not name asks first, and removing a ticket always asks. Text for a working
agent goes in at once, and the agent reads it at its next step; text for an
agent that asks a question waits until you answer it in its tab.

The chat checks for a newer tkt release when it opens and every six hours,
and names it under the board. /update installs it with tkt update, then offers
to quit: the chat runs the old tkt until you reopen it with the command it
prints. A development build gets no notice, and /update does not replace it.

Tickets in auto run in tkt auto loops that outlive the chat, so they keep
moving, and notify you, after you close it. A loop that pauses for you goes on
by itself once you act, such as answering the agent in its tab. tkt agent also
starts tkt watch for the repository when none runs, which takes the upkeep
steps for every ticket: it syncs a moved base, fixes failing checks once per
head, and removes a ticket once finish-ticket merged it. The board's heading
says watch on or watch off.

The chat is apart from any pi you run yourself. It reads none of ~/.pi/agent:
not your extensions, skills, prompt templates or themes, and not the project's
AGENTS.md or CLAUDE.md. It keeps its own settings, logins and sessions in
${XDG_CONFIG_HOME:-~/.config}/tkt/pi. Log in to a model provider once with
/login inside the chat.

The chat brings two themes of its own, tkt-dark and tkt-light, and picks the
one that suits the terminal's background. Overlays such as /board and /peek
draw on a panel of their own, so they read well on a transparent terminal. A
theme you pick in /settings wins from then on.

pi runs in the repository's root, where it keeps the sessions, so --continue
picks up the last chat about this repository from any of its worktrees. When
you quit, the chat prints the command that resumes it: tkt agent --session
ID. Flags after -- go to pi as they are, such as tkt agent -- --thinking high;
pi --help lists them.

In config.toml, an [agent] table picks the model and loads more pi extensions,
such as one that adds a model provider (tkt help config). --model overrides the
model for one run. Without [agent] model, pi starts on its own default: in
/model, press Ctrl+S on a model to make it the default for new chats.

tkt unpacks the bundled pi the first time, under
${XDG_DATA_HOME:-~/.local/share}/tkt/pi. Set TKT_PI to run another pi binary
instead; tkt doctor shows which pi tkt agent runs.

tkt agent replaces itself with pi, so it needs a terminal and prints no result.
--dry-run prints how it would start pi, and with --json the exact command line
and environment.
