tkt start creates or reuses the ticket's worktree through worktrunk, opens a
herdr tab named after the ticket, starts an agent in build mode (Claude Code
with --dangerously-skip-permissions, OpenCode on its Build agent) and sends it
the prompt, typically the dispatcher's start-ticket block.

A new branch starts from the base on the remote, such as origin/main: tkt
fetches it first, so the plan starts from the code the base holds now. When
the fetch fails, the branch starts from the local base.

The ticket's tab gets TMPDIR set to a private directory, such as
/tmp/tkt-acme-app-ACM-12-123456, so agents of two tickets never write the
same temporary file. Every tab tkt opens for the ticket gets the same one,
and tkt done removes it. OpenCode runs its tools in its own service, outside
the tab, so its agents get the directory through tkt's plugin (tkt help
hook).

Without an ID, tkt start takes the first ticket id in the prompt; with both,
they must match. Without a prompt, it sends the start stage line. --prompt -
reads the prompt from stdin, which keeps a long prompt out of your shell
history; --prompt-file reads it from a file.

The prompt's Model: line, when it has one, picks the preset (tkt help config);
--as picks one yourself.

After the start, tkt start starts a tkt auto loop for the ticket, in a
session of its own, so the ticket drives itself once you approve the plan:

  --auto       the default: the loop waits for you to approve the plan, in
               the plan viewer or with tkt approve, and never approves it
               itself; from there it drives the ticket to human
               verification.
  --manual     no loop: you drive each step.
  --auto-plan  the loop approves the plan too, as tkt auto --auto-plan does.
  --yolo       the loop carries the ticket to the merge with nobody
               watching, as tkt auto --yolo does.

[start] mode = "manual" in config.toml makes manual the default. tkt auto
needs GitHub and gh; elsewhere a start stays manual and says so. The loop
writes to auto-ID.log in the repository's tkt directory, and tkt auto ID
--stop stops it.

tkt start refuses when an agent already runs in the worktree: use tkt run for
a fresh session, or tkt resume to bring back the last one. When the agent stops
at a startup dialog, answer it in the tab and rerun the same tkt start: it
continues where it stopped.

--scratch NAME starts work that has no ticket. tkt start makes the worktree
and branch NAME and a tab named NAME, starts the agent and sends it nothing.
NAME takes letters, digits, '-' and '_', and must not be a ticket id. Other
tkt commands work on tickets only, so they do not see this worktree; remove
it with wt remove NAME.
