tkt send types text into the ticket's running session and waits until the
agent takes it. The session keeps its whole conversation, so use it to ask for
changes to a plan, or to answer a question the agent asked in its last
message.

It refuses while the agent works (tkt wait blocks until it is done) and while
it waits in its own dialog, such as a question with options: typed text does
not reach that dialog, so answer it in the ticket's tab. tkt show ID --screen
prints what the dialog asks.

--steer types the text in while the agent works, to steer it mid-task.
Claude Code and OpenCode hold the text and read it at their next step; the
result says steered. A question in the agent's dialog still refuses it.

--wait queues the text instead: tkt send waits until the agent stops working,
stops waiting on its own background task, and has no question open, then
types the text in. With --steer, it waits only for the question to close. It
holds no lock while it waits, so tkt auto and the other commands go on.

To start a stage in a fresh session instead, use tkt run. To approve a plan,
use tkt approve.
